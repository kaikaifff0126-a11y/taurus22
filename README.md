# Taurus 视觉学习与选拔代码

kai 的 C++ / OpenCV 学习项目，记录相机标定、装甲板检测与 PnP 距离估计实践。本仓库是 2026-10-18 面试后代码归档，保留当时的源码实现，并非经过完整验证的比赛视觉系统。

## 文件

- `装甲板识别.cpp`：读取视频，HSV 分割、形态学处理、轮廓与灯条筛选、灯条配对、PnP、距离与位置显示。
- `chessboard.cpp`：棋盘格角点检测、亚像素细化与相机标定练习。
- `taurus1.slnx` / `taurus1.vcxproj` / `taurus1.vcxproj.filters`：Visual Studio 工程。目前工程默认只编译装甲板识别程序。

## 环境与运行

原环境为 Windows、Visual Studio 2026（v145 工具集）、OpenCV 4.14.0，工程采用 C++20。

1. 安装 Visual Studio 的 C++ 桌面开发组件及 OpenCV。
2. 打开 `taurus1.slnx`，选择 `x64`。原工程 Win32 配置未设置 OpenCV。
3. 修改项目属性中的 OpenCV 包含目录、库目录、依赖库。原路径为 `C:\opencv\opencv\build`，Release 使用 `opencv_world4140.lib`，Debug 使用 `opencv_world4140d.lib`，其他版本需要改库名。
4. 确保相应 DLL 所在目录在运行环境的 PATH 中。
5. 修改源码中的视频路径和标定文件路径，准备对应素材后编译运行。按 Esc 退出视频。

源码中保留的本机路径：

| 用途 | 路径 |
|---|---|
| 视频 | `C:/TestVideo/8.4第二场_clip_194.800_204.avi` |
| 棋盘格图片 | `C:/calibration_images/calibration_images/*.png` |
| 标定结果 | `C:/cameracaliberate/camera.yml` |

切换到棋盘格程序时，将其加入工程参与编译，并排除装甲板程序；两份源文件都有 `main()`，不要同时生成。

视频、标定图片、实际标定参数、第三方课程素材、VS 缓存和编译产物未上传。其他用户必须自行提供有权使用的素材和适用的相机标定参数。

## 检测流程

视频帧 → 高斯模糊 → BGR 转 HSV → inRange → 开运算 → 外轮廓 → 旋转矩形 → 长宽比与倾角筛选 → 灯条两两配对 → PnP → 画框、中心与距离。

HSV 范围及配对阈值针对当时素材调节，并非所有光照和视频通用。

代码从每根灯条两条短边的中点获取上下端点，图像点顺序是左上、左下、右下、右上。物体模型位于 X=0 平面，使用 0.135 m 和 0.056 m 的模型尺寸，输出距离单位为米。必须确认模型的物理点与所检测端点对应。

读取标定文件的标签名为 **`CameraMatrix`** 和 **`diffcoeffs`**，大小写与拼写必须匹配；不要直接套用其他示例的 `cameraMatrix` / `distCoeffs` 标签。

## 已知限制与后续改进

- **标定程序存在多视图数据累积问题**：`if (found)` 内重新定义了点集容器，随后立即标定并覆盖 YML，因此每次使用的只是当前一张图，最后保存的也不是所有图片联合标定的结果。正确改进方向是：成功检测后在外层容器累积对应点，在整个图片循环结束后统一标定和保存。
- 标定中内角点为 11×8，格长为 50（应与实际标定板及单位对应）；需要核对题目数据，不要把方格数量误当内角点数量。
- 棋盘图读取失败检查、不同图像尺寸检查、重投影误差分析尚未补齐。
- 装甲检测读取标定矩阵，但未验证其对应的视频分辨率、成像设置和标定质量。
- 当前无识别耗时统计、数字分类、全局灯条配对或时序跟踪。多目标场景可能出现重复配对。
- PnP 返回成功不等于物理位姿可靠；当前没有完整的正深度、重投影与异常跳变筛选。
- 显示的中心为水平外接框中心，在强透视下不等同于物理中心的精确投影。
